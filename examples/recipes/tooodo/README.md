# Tooodo 待办接入

每分钟从 Tooodo 现有 HTTP 接口采集未完成、进行中的待办。“本人处理”只留事件，不派给模型；“自动化处理”且未完成的任务交给 Codex。已有进行中任务不自动接管。无需修改 Tooodo、内核或协议，也不创建来源密钥。

多个项目时，每条新自动化待办先用中台卡片请本人选择项目，确认后自动实施；项目选项来自本机设置，不从正文猜目录。选“暂不执行”后保持待办原样；再次安排时在 Tooodo 修改待办后保存，使版本递增。只有一个配置项目时自动选用。多于三个项目时卡片分页展示。所有项目实施共用并发 1，避免同时修改同一个工作区。

## 启用

1. 安装并启动 Tooodo，确认 `config/access.json` 存在。将本目录复制到固定的私有目录（例如 `~/.agent-autoloop/integrations/tooodo/`），复制 `settings.example.json` 为 `settings.json`，填写实际服务、数据目录和项目。设置文件由本人维护，不交给待办正文改写。
2. 将 Tooodo 已安装的 stdio MCP 入口接到执行 Codex 的账号；例如 `codex mcp add tooodo -- /绝对路径/node "/Users/you/Library/Application Support/Tooodo-app/mcp.mjs"`。先验证工具发现、查询、领取、进展和状态接口。使用 Tooodo 自带 MCP，由其读取本机凭据；令牌不写进规则、命令参数或事件。Codex 使用 `edit`，不放宽到完整权限。
3. `node setup.ts /绝对路径/settings.json 接单电脑 /绝对路径/rules.json` 合并配置，再运行 `agent-autoloop check`。保留原通知通道和其他规则；不重启服务。重复安装会拒绝覆盖，原规则备份为 `rules.json.tooodo-backup`。之后编辑项目设置时同步更新对应规则（固定 cwd 和可发事件类型），不要只改设置。

## 行为和边界

Codex 从 Tooodo 读取完整正文、原话、图片和进展，条件领取成功后开始，追加处理结果，通过检查才标记完成并读回核实。等待本人、已有其他执行者领取、处理方式改变、完成或删除的任务不会从头重做；中台失败重派和卡片续办沿用原会话。实施约定见 [implement.md](implement.md)。本模板不替项目提交、推送或发布。

事件编号由数据代次、待办编号和版本组成，重复轮询由中台去重；不会自行推进需要确认的游标。每轮最多 100 条，超过一页时按分钟轮换页面，通常在页数对应的分钟数内覆盖全量，列表并发变化时由后续轮询补齐。已完成、备忘、已删除记录不采集，不提供全量历史镜像；中台保存的是采集到的事件。进展中的任务也记录观察事件，但不会重新派给模型。完整需求通过 MCP 重读，事件摘要最多 200 字、详情最多 4000 字。

采集失败使用中台现有重试；需要本人恢复 Tooodo 连接时，正在实施的 Codex 用卡片结束本轮。卡片发送及回答者鉴权沿用已有通道。测试只使用临时 HTTP 服务和模拟接口；启用本机采集不代表已有真实自动化待办实施通过。首次使用应给一条范围明确、可核验的小任务。
